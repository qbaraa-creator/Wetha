# فسحة

تطبيق ويب تقدمي (PWA) عربي RTL ينفّذ [وثيقة متطلبات المنتج](docs/PRD.md)
المحدّثة إلى الإصدار 1.6.

يعرض توقع سبعة أيام لجدة في صفحة واحدة، مع مخطط «أفضل أوقات الفسحة» اليوم وخلال الأسبوع.
لا تُعد الساعة مناسبة إلا عند تزامن اتجاه شمالي/شمالي غربي، وسرعة بين 15 وأقل من 35 كم/س،
ورطوبة أقل من 50%. الشريط الملوّن هو الأساس لكل يوم ويظهر مباشرة، مع العظمى والصغرى واحتمال
الهطول الموجب. عند اختيار الساعة تظهر قيمها وأسباب حالتها. أرقام الفترات الخمس داخل «التفاصيل»
فقط، دون بطاقات لعدادات المطابقة. هذا تقييم للتفضيلات لا لسلامة الخروج.

## مجلد واحد للرفع إلى GitHub

هذا المجلد هو المصدر الوحيد للمشروع. ارفع **محتوياته إلى جذر المستودع**، بحيث يظهر
`package.json` و`index.html` مباشرة في الجذر، لا داخل مجلد إضافي باسم المشروع.

```text
تطبيق الطقس اليومي/
├── .github/       إعدادات الاختبار والنشر وتحديث الاعتماديات
├── docs/          وثيقة متطلبات المنتج
├── public/        أيقونات التطبيق بأحجامها المطلوبة
├── scripts/       توليد الأيقونات وفحص نسخة النشر
├── src/           الشيفرة والاختبارات، دون نسخ مكررة
├── README.md      دليل المشروع
├── SECURITY.md    سياسة الإبلاغ الأمني
├── index.html     مدخل التطبيق
├── package.json   أوامر المشروع والاعتماديات
├── package-lock.json
└── ملفات الإعداد في الجذر، بما فيها الملفات المخفية
```

لا تحذف الاختبارات أو ملفات الإعداد: يحتاجها فحص النشر. `package-lock.json` يثبت نسخ
الاعتماديات وليس نسخة مكررة من `package.json`، والأيقونات المختلفة مطلوبة لأحجام وأوضاع PWA.
على macOS يُظهر الاختصار `⌘⇧.` الملفات المخفية؛ يجب تضمين `.github` وملفات الإعداد عند الرفع.

لا ترفع `node_modules/` أو `dist/` أو `coverage/` أو `.claude/` أو `.DS_Store`.
هذه حزم ومخرجات وإعدادات محلية وليست مصدر التطبيق؛ يعيد `npm ci` إنشاء الحزم،
ويُنشئ البناء والتغطية مخرجاتهما عند الحاجة. لا تنشئ مجلد رفع مكررًا داخل المشروع.
ملف `.gitignore` يمنع تتبعها عند استخدام Git، لكنه لا ينقّي الملفات التي تختارها يدويًا للرفع.

## الاختبارات

```bash
npm test
```

اختبارات آلية تغطي قواعد المجال وعقد المزود ومدقق التخزين ومكوّنات الواجهة،
بما فيها لوحة المفاتيح واللمس وRTL والتباين ورسائل الخطأ والتحذير والبيانات القديمة.
يعرض الأمر العدد الفعلي للاختبارات ونتائجها؛ اختبارات العقد الحي منفصلة وتُتخطى افتراضيًا.
تشمل الاختبارات مصفوفة الاتجاهات الثمانية ونطاقات السرعة والرطوبة، وتزامن الشروط ساعة بساعة،
وظهور جميع أسباب عدم المطابقة والبيانات الناقصة، ومنع شفافية نصوص الفترات المنقضية،
ورفض حرارة خارج `−90…60°C` أو عظمى أقل من الصغرى في كلا مساري التخزين.
تُختبر معاملات IndexedDB باستخدام `fake-indexeddb`، مع مسارات السقوط إلى localStorage وحالات
الإلغاء والحظر والسجلات التالفة؛ لا تُحاكى نتيجة طبقة التخزين نفسها.

فحوص الجودة التي تشغّلها عملية النشر نفسها:

```bash
npm run lint
npm run format:check
npm run test:coverage
```

حد التغطية الحاجب هو 80% للتعليمات والفروع والدوال والأسطر.
لملف `forecastStore.ts` حد مستقل: 90% للتعليمات والدوال والأسطر و85% للفروع، حتى لا يخفي
المتوسط العام تراجع تغطية التخزين.

اختبار التكامل يتصل بالمزود فعليًا ويتحقق من عقده — خاصة وحدة `moon_phase` — ولا يعمل افتراضيًا
حتى لا يعتمد البناء على الشبكة:

```bash
npm run test:integration
```

بعد البناء يمكن فحص سلامة مخرجات PWA، ومسارات الملفات، وسياسة المحتوى، وملف Service Worker:

```bash
npm run test:pwa
```

## البناء والنشر

```bash
npm run build
```

يُنتج مجلد `dist` جاهزًا للرفع على أي استضافة ملفات ساكنة (Netlify، Vercel، GitHub Pages، Cloudflare Pages).
لا يوجد Backend ولا مفاتيح API. المسار الأساسي نسبي افتراضيًا، ويمكن ضبطه وقت البناء عبر `VITE_BASE_PATH`:

```bash
VITE_BASE_PATH=/اسم-المستودع/ npm run build
```

معاينة النسخة المبنية محليًا:

```bash
npm run preview
```

إذا بُنيت النسخة لمسار مستودع، مرّر المسار نفسه عند المعاينة:

```bash
VITE_BASE_PATH=/Wetha/ npm run preview
```

إعادة توليد أيقونات PWA بعد أي تغيير في هوية الأيقونة:

```bash
npm run icons
```

### النشر على GitHub Pages

يتضمن المشروع سير عمل في [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). عند الدفع إلى فرع
`main` يشغّل الاختبارات والبناء وفحص PWA، ثم ينشر `dist`. يحسب السير تلقائيًا المسار الصحيح سواء كان
المستودع موقع الحساب (`owner.github.io`) أو موقع مشروع (`owner.github.io/repository`).

بعد إنشاء المستودع ورفعه، اختر في GitHub: **Settings → Pages → Source: GitHub Actions**. لا يحتاج
المشروع إلى أسرار أو مفاتيح API. يتابع Dependabot تحديث حزم npm وإجراءات GitHub دوريًا.

## أين تُعدَّل الإعدادات

كل ما هو قابل للضبط في ملف واحد: [`src/config/appConfig.ts`](src/config/appConfig.ts).

| ما تريد تغييره | الثابت |
|---|---|
| الموقع والإحداثيات والمنطقة الزمنية | `LOCATION` |
| عدد أيام التوقع | `FORECAST_DAYS` |
| عتبات سرعة الرياح | `SPEED_THRESHOLDS` |
| عتبات الرطوبة | `HUMIDITY_THRESHOLDS` |
| حدود صلاحية الحرارة لدى المزود والتخزين | `TEMPERATURE_LIMITS_C` |
| حدود فترات اليوم الخمس | `DAY_PARTS` |
| لون كل قطاع اتجاه | `DIRECTION_SEVERITY` |
| نسبة الاتجاه العام قبل وصف الرياح بالمتقلبة | `DOMINANT_DIRECTION_MIN_SHARE` |
| مهل التحديث والمهلة الزمنية وإعادة المحاولة | `REFRESH_POLICY` |
| تسميات الحالات ورموز الوصول | `SEVERITY_SHORT_LABELS` و`SEVERITY_GLYPHS` |
| نسبة مصدر البيانات | `DATA_ATTRIBUTION` |

تغيير المدينة لا يتطلب لمس أي مكوّن أو أي قاعدة تصنيف: عدّل `LOCATION` فقط.
قيم الألوان مكرّرة كمتغيرات CSS في أعلى [`src/styles.css`](src/styles.css) لأن المتصفح يحتاجها للرسم؛
هي المكان الوحيد الآخر الذي يذكر قيمة لون.

## قرارات تنفيذ مثبتة

- **تنعيم الاتجاه يغيّر الاتجاه واللون معًا.** الساعة الشاذة الوحيدة المحاطة باتجاه واحد تُدمج معه
  ويُعاد حساب حالتها من الاتجاه الجديد؛ ولذلك وُضع استثناء القسم 5.6: الساعة التي حالتها الخام حمراء
  لا تُدمج أبدًا. يظهر في التفاصيل الساعية نجمة `*` على كل ساعة مُنعَّمة حتى يبقى الأمر قابلًا للتحقق.
- **ساعات اليوم الحالي المنقضية تدخل** في المتوسطات وعدّادات الألوان وترتيب الأسبوع، لأن القسم 1.3
  يعرّف اليوم بأنه `00:00–24:00`. تتميز صفوف جدول الفترات المنقضية بخلفية مختلفة وحدود متقطعة،
  لا بشفافية تخفض تباين النص. يوضح نص الوصول أنها انقضت.
- **الشريط أساس بطاقة اليوم**: ظاهر دون فتح التفاصيل. أُزيلت بطاقات الفترات ذات عدادات المطابقة
  وأسبابها المجمعة، لا نُقلت إلى موضع آخر. الأسباب الدقيقة باقية عند اختيار ساعة من الشريط.
- **أرقام الفترات داخل التفاصيل فقط**: فجر 0–6، صباح 6–12، ظهر 12–16، عصر 16–19، ليل 19–24؛
  تقسيم عرض ثابت لا مواقيت فلكية. الجدول يعرض حدود الفترة ومدى السرعة ومتوسط الرطوبة بألوان
  محايدة؛ القيم الناقصة شرطة. لا يُستنتج لون الساعة من متوسط الفترة.
- **مصفوفة ساعية واحدة** في `outdoorActivity.ts`: الحالة الأشد بين الاتجاه والسرعة والرطوبة،
  باستخدام العتبات المعتمدة دون تقريب. تستخدمها نوافذ الأنشطة والشريط؛ لا تُدمج أغلبيات
  مأخوذة من ساعات مختلفة. البيانات الناقصة محايدة حتى لو عُرف سبب آخر، والأسباب المعروفة لا تُخفى.
  تظهر كل الأسباب البرتقالية والحمراء، مع تقديم الأشد. «أقل من المفضّل» لا تعني خطرًا.
  قراءة الساعة تحفظ كسور السرعة والرطوبة كي لا يناقض الرقم المقرب سبب الحالة؛ تبقى ملخصات
  الفترات مقربة داخل جدول التفاصيل.
- **الحرارة والمطر للعرض فقط**: العظمى والصغرى بالمئوية، وأعلى احتمال هطول يظهر إن تجاوز الصفر.
  غياب الاحتمال لا يُعرض كصفر. لا تدخل هذه الحقول في عتبات الرياح أو الرطوبة أو معايير الأنشطة.
  يستخدم المزود والتخزين حدود الحرارة نفسها؛ المزود يفرغ الحقول التالفة مع تحذير، والتخزين يرفض
  السجل التالف كاملًا. مخطط التخزين 4 يرفض تصنيفات السرعة القديمة ويجلب توقعًا محسوبًا بالقواعد
  الجديدة؛ يلزم اتصال بالشبكة لأول تحديث بعد هذه الترقية. مفاتيح التخزين ومسار GitHub Pages لم تتغير بتغيير الاسم.
- **لا توجد صفحة يوم مكررة**: كل يوم يفتح تفاصيله داخل بطاقة الأسبوع الأصلية، فبقي مسار قراءة واحد.
- **الاتجاه المتقلب يحتفظ بحالته الدلالية**: تُدمج حالتا الاتجاهين وفق قاعدة «الحالة الأشد»؛ لذلك
  «شمالية غربية / شمالية» خضراء لأن الاتجاهين أخضران، وليست حالة محايدة.
- **أفضل أوقات الأنشطة شرط متزامن**: لا يكفي أن تكون الرطوبة مناسبة وحدها أو الرياح مناسبة في ساعة
  مختلفة؛ يجب تحقق الاتجاه والسرعة والرطوبة في الساعة نفسها. يُعرض المتبقي من اليوم ونظرة الأيام السبعة.
- **عتبات السرعة بلا تداخل**: أقل من 15 أحمر، 15–أقل من 25 أخضر. نطاق 25–أقل من 35 أخضر
  للشمالية والشمالية الغربية، وبرتقالي لبقية الاتجاهات؛ و35 فأكثر أحمر دون استثناء.
  يظل لون الاتجاه مستقلًا، فلا تصبح الجهات غير المفضلة خضراء. الرطوبة أقل من 50 أخضر، 50–أقل من 65 برتقالي،
  و65 فأكثر أحمر.
- **الشريط الساعي ظاهر مباشرة وموحّد**: حالة واحدة لكل ساعة، مع محور وهدف لمس واحد.
  الاختيار بالنقر أو اللمس أو السحب أو الأسهم، لا بمرور الفأرة. تبقى القراءة عند فقد التركيز
  أو الانتقال إلى التفاصيل كي لا يتحرك الزر أثناء النقر؛ يزيل `Escape` الاختيار.
  وهو محطة Tab واحدة مع تنقّل بالأسهم داخلها (`role="listbox"`)، بدل 24 محطة لكل شريط.
  قارئ الشاشة يتبع الخيار النشط عبر `aria-activedescendant` مرة واحدة، وتبقى لوحة القراءة المرئية
  منفصلة وغير معلنة لتجنب تكرار النطق (القسمان 9.3 و21.7). القراءة المرئية تعرض القرار وجميع
  أسبابه أولًا ثم قيم الساعة. جدول «كيف يُحسب التقييم؟» يقرأ العتبات من إعدادات الحساب نفسها.
- **الأنماط تسند الألوان في الأشرطة**: أخضر سادة، برتقالي مخطط صاعد، أحمر مخطط هابط وأغمق،
  فتبقى الحالات مميزة في التدرج الرمادي.
- **أسماء الألوان لا تتكرر بصريًا** بجانب كل رمز؛ تبقى في `aria-label` و`title` لقارئات الشاشة
  ولمن يحتاج تفسير الحالة.
- **التصميم Mobile-first**: رأس مختصر، أهداف لمس لا تقل عن 44 بكسل، بطاقات أرقام ذات رموز،
  وفترات خضراء في شرائح زمنية مستقلة تمنع تشابك RTL. لا تظهر نقطة خضراء عند عدم وجود ساعات مناسبة.
- **الأيام الأفقية متاحة بلوحة المفاتيح**: حاوية مسماة ومحطة Tab واحدة؛ الأسهم تمرر بطاقة كاملة،
  وHome/End يصلان للطرفين. لا تُعترض مفاتيح التمرير عند اتساع الشاشة لعرض جميع الأيام.
- **الوحدة غير المتوقعة تُرفض ولا تُحوَّل صامتًا**: يُفرَّغ الحقل ويُسجَّل تنبيه تقني في `forecast.warnings`.
- **البيانات الخارجية لا تُوثق ضمنيًا**: تُفحص استجابة المزود والمصفوفات والوحدات والنطاقات والمنطقة الزمنية،
  كما يُرفض سجل التخزين كاملًا إذا خالف المخطط الداخلي.

## الحماية

- سياسة محتوى (CSP) تقصر السكربتات والموارد على الموقع، والاتصال الشبكي على Open-Meteo فقط.
- في خادم التطوير فقط يسمح `worker-src` بمصدر `blob:` لعامل إعادة اتصال Vite HMR. يبقى
  ملف HTML المصدر وبناء الإنتاج على `worker-src 'self'`، ويتحقق فحص PWA من عدم تسرب السماح.
- لا تُحقن استجابة المزود كـ HTML، ولا توجد رموز وصول أو أسرار في المتصفح.
- سياسة Referrer مقيدة، ومصادر النماذج والكائنات محظورة.
- فحص اعتماديات التشغيل بـ`npm audit --omit=dev` حاجب للنشر، والفحص الكامل استشاري غير حاجب حتى
  لا توقف ثغرة في أداة اختبار موقعًا ساكنًا لا يشحن تلك الأداة. توجد تحديثات Dependabot مجدولة.
- توجد [سياسة إبلاغ أمني](SECURITY.md) مهيأة لاستخدام تقارير GitHub الخاصة بدل كشف الثغرات علنًا.

> GitHub Pages يفرض HTTPS، لكنه لا يتيح ضبط رؤوس HTTP مخصصة لكل مشروع. لذلك سياسة المحتوى موضوعة
> في HTML. توجيه `frame-ancestors` لا يعمل أصلًا داخل `<meta>`، ولذلك لا يمكن فرض منع التأطير على
> GitHub Pages. الأثر منخفض هنا لعدم وجود مصادقة أو عمليات تغيّر حالة. إذا نُقل التطبيق إلى استضافة
> تدعم الرؤوس، يجب إرسال `Content-Security-Policy: frame-ancestors 'none'` مع بقية رؤوس الحماية.

[Open-Meteo Forecast API](https://open-meteo.com/) — بلا مفتاح، مع دعم CORS، بوضع `Best Match`.

النسبة معروضة في تذييل التطبيق كما يوجب الترخيص (FR-16).
**قبل أي استخدام تجاري** يجب مراجعة خطة الاستخدام التجاري وشروطها؛ شروط الاستخدام الشخصي لا تمتد
تلقائيًا إلى الاستخدام التجاري.

القيم توقعات نموذجية وليست قياسات محطة محلية لحظية، والواجهة تصرّح بذلك.

## ما لم يُنفَّذ في هذه الجولة

هذه هي قائمة الانحرافات عن الوثيقة (مطلوبة بموجب القسم 26):

1. **صور أو تسجيل قصير للواجهة** (القسم 26، البند 8): جرت مراجعة بصرية فعلية عند 320 و768 و1440 بكسل
   وأُصلحت مشكلات ظهرت فيها، لكن لم تُصدَّر ملفات صور إلى المستودع.
2. **اختبار Safari على iOS وmacOS وEdge** (القسم 20 — التوافق): البناء يستخدم خصائص CSS منطقية
   (`inset-inline-start`) و`IndexedDB` وService Worker، وكلها مدعومة في آخر إصدارين من هذه المتصفحات،
   لكن لم يجرِ فتح فعلي عليها.
3. **رفع التعديلات الحالية والتحقق من النسخة المنشورة**: هذه الجولة محلية؛ لا تفترض أن نسخة
   GitHub Pages تحمل هذه التغييرات قبل رفعها ونشرها، ثم فحصها على الأجهزة الفعلية.

نجاح الاختبارات والبناء لا يغني عن فحوص المتصفحات والأجهزة المذكورة أعلاه قبل اعتماد الإطلاق النهائي.
